# 飞书部署成功通知

## 模式

| FEISHU_MODE | 行为 |
| --- | --- |
| OFF（默认） | 不通知 |
| MOCK | 部署成功后只在控制台预览正文，不读取凭据、不发送请求 |
| LIVE | 使用真实凭据和签名发送到飞书群 |

## 首次启用

通知脚本依赖 Python 3，已加入 jenkins/Dockerfile。启动 Docker Desktop 后执行：

```powershell
cd D:\项目\cicdproject-platform
docker compose up -d --build jenkins
```

Jenkins 数据卷仍保留账号、任务和凭据。运行一次任务后，Build with Parameters 页面会显示新增的 FEISHU_MODE 参数；首次读取新 Jenkinsfile 时默认 OFF。

选择 MOCK，再运行一次 main 分支部署。日志应出现 MOCK 通知正文。假数据仅作展示，不会发送。

## 真实配置

在飞书目标群添加自定义机器人，开启签名校验，取得 Webhook 和签名密钥。
在 Jenkins → Manage Jenkins → Credentials 添加两项 Secret text：

| ID | Secret |
| --- | --- |
| feishu-webhook | 真实 Webhook URL |
| feishu-secret | 真实签名密钥 |

占位示例（不能用于真实发送）：

- Webhook：https://open.feishu.cn/open-apis/bot/v2/hook/DEMO-NOT-A-REAL-TOKEN
- Secret：DEMO-NOT-A-REAL-SECRET

将 FEISHU_MODE 改为 LIVE。Jenkins 通过 withCredentials 临时注入环境变量；Python 使用时间戳和 HMAC-SHA256 签名发送。凭据不写入源码或镜像，不打印到日志。

消息包含任务、构建编号、分支、镜像和构建链接。localhost 地址仅适用于部署机器，团队使用时应改为团队可访问的地址。

## 行为边界

- 仅成功部署并通过健康检查后通知；仅构建、部署失败不发送成功消息。
- 通知失败会输出警告，保留部署成功结果。
- 接收方返回 HTTP 200 仍可能是业务失败，脚本会检查 code / StatusCode。
- 本地验证命令：python scripts/notify-feishu.py --mock
